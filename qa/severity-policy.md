# Severity Policy

**상태:** PLANNED / NOT EXECUTED

Severity는 결함의 영향도를 기준으로 판단한다. Priority는 처리 순서를 뜻하며 Severity와 별도로 기록한다.

---

## Severity 기준

| 등급 | 기준 | 예시 |
| --- | --- | --- |
| S1 | 핵심 기능 불가, 데이터 훼손, 중대 보안·안전 문제 | 승인 이력 유실, secret 노출, DecisionLog 변조 가능 |
| S2 | 주요 기능 오류 | AI 리스크 분석 실패, 판단 제출 실패, 승인 API 오류 |
| S3 | 우회 가능한 부분 오류 | 특정 inputType에서 context 일부 누락, 표시 오류 |
| S4 | 낮은 영향 | 문구 오탈자, 낮은 영향의 UI 정렬 문제 |

---

## Priority 기준

| 등급 | 기준 |
| --- | --- |
| P0 | 즉시 수정 필요. 배포 차단 가능 |
| P1 | 다음 릴리스 전 수정 필요 |
| P2 | 계획된 개선 주기에 포함 |
| P3 | 낮은 우선순위. backlog 관리 |

---

## AI 산출물 관련 가중 판단

다음 항목은 기본 영향도보다 높게 평가한다.

| 항목 | 이유 |
| --- | --- |
| AI 산출물과 사람 승인 구분 실패 | 책임 소재와 감사 추적 불가 |
| 모델·prompt version 누락 | 동일 판단 재현과 변경 영향 분석 불가 |
| code lineage 누락 | 어떤 코드가 어떤 요청에서 생성됐는지 추적 불가 |
| secret masking 실패 | 보안 사고 가능 |
| audit log 변조 가능 | 승인·의사결정 신뢰성 훼손 |
